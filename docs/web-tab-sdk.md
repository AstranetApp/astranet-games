# Astranet Web Tab SDK

Вкладка сообщества Astranet — это веб-приложение, открываемое внутри клиента:
в веб-версии в элементе `<iframe>`, в мобильном приложении в WebView.
Приложение остаётся обычным сайтом; от клиента ему требуется единственная
возможность — получить идентификатор текущего игрока.

Ниже описан полный протокол: один запрос и один ответ.

## Назначение

Без идентификации прогресс сохраняется только в `localStorage`: при смене
устройства он теряется, а турнирная таблица заполняется записями одного
и того же человека из разных браузеров.

Astranet предоставляет анонимный pairwise-токен — 22 символа base64url,
стабильные для пары «игрок + сайт». Один игрок получает одинаковый токен
в веб-клиенте и в мобильном приложении; два разных сайта получают разные
токены, которые невозможно сопоставить между собой. Данные аккаунта
(идентификатор пользователя, адрес электронной почты, профиль) не передаются.

## Формат сообщений

Запрос приложения к клиенту:

```js
{ astranet: 'identity.request', id: '<идентификатор запроса>' }
```

Ответ клиента:

```js
{ astranet: 'identity.response', id: '<идентификатор запроса>', token: '<22 символа>' }
{ astranet: 'identity.response', id: '<идентификатор запроса>', error: '<причина отказа>' }
```

Поле `id` обязательно: ответы поступают в общий обработчик события `message`,
и по нему приложение отличает свой ответ от прочих сообщений, которыми
обменивается страница внутри `iframe`.

## Транспорт

Формат сообщений одинаков для всех платформ, различается способ отправки:

| Среда выполнения | Отправка запроса | Получение ответа |
| --- | --- | --- |
| Веб-клиент (PWA), приложение в `<iframe>` | `window.parent.postMessage(req, '*')` | событие `message` на `window` |
| Android и iOS, приложение в WebView | `window.AstranetBridge.postMessage(JSON.stringify(req))` | событие `message` на `window` |

Наличие `window.AstranetBridge` служит признаком мобильного клиента и
проверяется первым.

Референсная реализация:
[`sdk.ts`](../games/happy-goi/client/src/astranet/sdk.ts).

## Требования к реализации

### Таймаут обязателен

Клиент может не ответить: устаревшая версия приложения, запуск вне Astranet,
ошибка на стороне клиента. Без ограничения времени ожидания приложение
останется на экране загрузки. В референсной реализации таймаут составляет
3 секунды, после чего выполняется переход в гостевой режим.

### Гостевой режим как полноценный

Вне Astranet приложение должно оставаться работоспособным: идентификатор
генерируется локально (UUID в `localStorage`), функциональность доступна
в полном объёме, прогресс сохраняется в браузере. Этот же режим используется
при локальной разработке, что обеспечивает его постоянную проверку.

```js
export async function resolveAuth(): Promise<Auth> {
  try {
    const token = await astranetGetIdentity();
    return { kind: 'astra', header: 'astra ' + token };
  } catch {
    return { kind: 'guest', header: 'guest ' + guestId() };
  }
}
```

### Обращение с токеном

Токен является bearer-идентификатором: владение им равносильно
подтверждению личности игрока. Отсюда следуют требования:

- не отображать в пользовательском интерфейсе;
- не передавать в составе URL — значение попадает в журналы веб-сервера,
  историю браузера и заголовок `Referer`;
- передавать только на собственный бэкенд и только в заголовке запроса;
- не хранить в базе данных в исходном виде.

В базу записывается результат хеширования, усечённый до 32 символов —
этого достаточно для использования в качестве первичного ключа, при этом
компрометация базы не позволяет действовать от имени игрока:

```js
const hashAuth = (s) =>
  createHash('sha256').update(SALT + '|' + s).digest('hex').slice(0, 32);
```

Соль генерируется однократно при первом запуске и хранится в той же базе
данных.

## Формат заголовка авторизации

Приложение передаёт идентификатор на собственный бэкенд в заголовке
`X-Player`:

```
X-Player: astra <token>
X-Player: guest <uuid>
```

Сервер разбирает заголовок регулярным выражением и не принимает сведения
о личности игрока из тела запроса:

```js
const m = /^(astra|guest) ([A-Za-z0-9_\-]{8,64})$/.exec(req.headers['x-player'] || '');
```

## Ограничения протокола

Протокол решает исключительно задачу идентификации. Он не авторизует
действия игрока и не подтверждает достоверность игровых результатов:
значение токена может быть подставлено средствами инструментов разработчика.
Проверка результатов выполняется на стороне сервера приложения —
см. раздел «Начисление очков на сервере» в [README](../README.md).
